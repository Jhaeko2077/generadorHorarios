============================================================
PROJECT NAME
============================================================

Academic Timetable Optimizer

Alternative internal codename:
SmartSchedule Institute

============================================================
PROJECT PURPOSE
============================================================

Create a web system that helps an institute generate academic schedules automatically.

The system must allow:

1. Teachers to register.
2. Teachers to define their working days, available time ranges, unavailable time ranges, preferred time ranges, maximum weekly hours, maximum daily hours, and maximum consecutive teaching blocks.
3. Administrators to manage programs, cycles, sections, courses, classrooms, labs, workshops, time slots, academic terms, and course offerings.
4. Administrators to generate optimized schedules using OR-Tools CP-SAT.
5. The scheduler to respect hard constraints and optimize soft constraints.
6. The system to recommend good time slots and rooms.
7. The generated schedules to vary between academic terms in a controlled and measurable way.
8. The administrator to view schedules by section, teacher, and room.
9. The system to detect conflicts, explain infeasibility, store schedule runs, export to Excel/PDF, and keep audit logs.

This project must look serious enough for an innovation contest. It should not feel like a toy CRUD app. The schedule generation must be mathematically grounded.

============================================================
HIGH-LEVEL PRODUCT DESCRIPTION
============================================================

The system has three user types:

1. Admin
   - Manages academic data.
   - Creates academic terms.
   - Creates courses, cycles, sections, rooms, and time slots.
   - Assigns teachers to course offerings.
   - Runs the OR-Tools schedule generator.
   - Reviews generated schedules, metrics, conflicts, and recommendations.
   - Exports schedules.

2. Teacher
   - Registers an account.
   - Completes profile.
   - Selects employment type.
   - Defines availability.
   - Defines preferred and discouraged time blocks.
   - Views assigned schedule.

3. Viewer/Read-only role
   - Optional.
   - Can view published schedules only.

For the MVP, implement Admin and Teacher. Viewer is optional but the schema can support it.

------------------------------------------------------------
Decision Variables
------------------------------------------------------------

Create Boolean decision variables:

x[(session_id, start_slot_id, room_id)] = 1
if session is assigned to that start slot and room.

Do not create impossible variables. Preprocess the domain first.

Only create x variables when:
- start slot can fit duration consecutively on the same day
- teacher is available or discouraged/preferred/available, but not unavailable
- section shift allows the slot
- room is active
- room type is compatible
- room capacity is enough
- room is not unavailable for any covered slot
- manual locks do not forbid it

This domain preprocessing is important for performance.

Also keep coverage:
covered_slots[(session_id, start_slot_id)] = list of time_slot_ids covered by duration_blocks.

------------------------------------------------------------
Hard Constraints
------------------------------------------------------------

Implement these as mandatory CP-SAT constraints.

1. Every session exactly once
For every session:
sum(x[session, start_slot, room] for all feasible placements) == 1

2. Teacher cannot be double-booked
For every teacher and atomic time slot:
sum(x[session, start_slot, room] where session teacher = teacher and placement covers slot) <= 1

3. Section cannot be double-booked
For every section and atomic time slot:
sum(x[session, start_slot, room] where session section = section and placement covers slot) <= 1

4. Room cannot be double-booked
For every room and atomic time slot:
sum(x[session, start_slot, room] where placement covers slot) <= 1

5. Teacher availability
Do not create variables for unavailable teacher placements.
Discouraged is allowed but penalized.
Preferred is allowed and rewarded or lower penalty.
Available is neutral.
No availability means unavailable by default.

6. Room compatibility
Do not create variables for incompatible room type.
If course requires lab, room type must match lab/workshop/computer_lab according to requirement.

7. Room capacity
Do not create variables when room capacity < section student_count.

8. Max weekly teacher hours
For each teacher:
sum(duration_blocks of scheduled sessions assigned to teacher) <= max_weekly_hours

Since all offerings already belong to teachers, this constraint should be satisfied by data, but still enforce it.

9. Min weekly teacher hours
For each teacher:
If min_weekly_hours > 0, try as soft target unless explicitly configured as hard.
For MVP, treat max as hard and min as soft.

10. Max daily teacher hours
For each teacher and day:
sum(duration_blocks scheduled for that teacher that day) <= max_daily_hours

11. Max consecutive blocks
For each teacher, day, and sliding window of size max_consecutive_blocks + 1:
sum(teacher_busy[teacher, slot] over window) <= max_consecutive_blocks

12. Manual locks
If a manual lock exists:
- Force the matching x variable to 1 if feasible.
- If not feasible, return infeasible diagnostic before or after solving.

13. Session consecutive blocks
A session with duration_blocks > 1 must cover consecutive blocks on same day.
This should be handled by feasible start slot preprocessing.

14. Section shift
For MVP:
- morning section should only use morning slots
- afternoon section should only use afternoon slots
- evening section should only use evening slots
- mixed can use any active slot

15. Do not schedule inactive data
Ignore inactive rooms, courses, sections, offerings, and time slots.

------------------------------------------------------------
Soft Constraints and Objective
------------------------------------------------------------

Build weighted penalty terms and minimize total penalty.

Default weights:
- teacher_discouraged_slot: 30
- teacher_non_preferred_slot: 8
- teacher_gap: 15
- section_gap: 20
- late_block: 5
- lab_scarcity: 25
- teacher_daily_concentration: 8
- fairness: 10
- diversity_repetition: 12
- target_load_balance: 5

Allow override from API payload.

Soft penalties:

1. Teacher discouraged slot penalty
If placement uses a discouraged teacher slot:
penalty += weight_teacher_discouraged_slot

2. Teacher non-preferred slot penalty
If teacher has preferred slots that day/week but placement uses available non-preferred:
penalty += weight_teacher_non_preferred_slot

3. Teacher gaps
Penalize idle holes between teacher classes in the same day.
Implement simple MVP approximation:
- Create teacher_busy[teacher, slot].
- For each teacher/day, if busy at earlier slot and later slot with free slots between, penalize gaps.
Simplify if necessary, but implement a reasonable version.

4. Section gaps
Same as teacher gaps, but for section.
This is more important than teacher gaps.

5. Late block penalty
Penalize evening or last block if avoidable, especially for morning/afternoon sections.

6. Lab scarcity
If a non-lab course uses a lab/workshop/computer_lab, penalize.
Do not allow this if room_type_required is strict classroom. If room_type_required = any, allow but penalize.

7. Teacher daily concentration
Penalize putting too much of a teacher's weekly load on one day even if within max_daily_hours.

8. Fairness by cycle/section
Avoid always assigning bad blocks to the same cycle/section.
Use a simple penalty:
- Late slots, discouraged slots, and gaps contribute to section penalty.
- Minimize max section penalty or add weighted sum plus max penalty variable if feasible.

9. Diversity from previous term
If previous assignments exist:
- Penalize assigning same course_offering/course-section-teacher to same day/time/room as previous term.
- Compute diversity_score after solving:
  diversity_score = percentage of comparable assignments whose time slot or room changed.
If no previous term exists, diversity_score = null or 1.0.

10. Teacher target load balance
If min_weekly_hours or target hours exists, penalize absolute deviation from target.
For MVP, because offerings are preassigned to teachers, this may be limited. Still compute a metric.

Objective:
model.Minimize(sum(weighted_penalty_terms))

Make objective transparent:
- Store each assignment penalty score.
- Store total soft penalty.
- Include a metadata breakdown by penalty type.

combined_score = soft_penalty_score - diversity_bonus

Keep simple but clear.

============================================================
CONSTRAINT MODELING GUIDE
============================================================

Use atomic time slots and duration coverage.

Example:
slot Monday block 1 = 07:00-08:00
slot Monday block 2 = 08:00-09:00
session duration_blocks = 2
start at block 1 covers block 1 and block 2.

Feasible placement:
(session_id, start_slot_id, room_id)

Variable:
x[(session_id, start_slot_id, room_id)] = model.NewBoolVar(...)

Every session:
model.AddExactlyOne(x for all placements of session)

Teacher overlap:
For each teacher and atomic slot:
model.Add(sum(x for placements of that teacher covering atomic slot) <= 1)

Section overlap:
For each section and atomic slot:
model.Add(sum(x for placements of that section covering atomic slot) <= 1)

Room overlap:
For each room and atomic slot:
model.Add(sum(x for placements in that room covering atomic slot) <= 1)

Daily hours:
For each teacher and day:
model.Add(sum(duration_blocks * x for placements of teacher on day) <= teacher.max_daily_hours)

Weekly hours:
For each teacher:
model.Add(sum(duration_blocks * x for placements of teacher) <= teacher.max_weekly_hours)

Consecutive blocks:
Create teacher_busy[(teacher_id, slot_id)] BoolVar or IntVar linked to placements.
For each teacher/day/window:
model.Add(sum(teacher_busy for slots in window) <= max_consecutive_blocks)

Manual lock:
Find placement matching lock.
model.Add(x[matching_placement] == 1)
If no matching placement, diagnostic: manual lock impossible.

Objective:
penalty_terms = []
Add weighted linear penalty terms.
model.Minimize(sum(penalty_terms))

============================================================
IMPORTANT SCHEDULER EDGE CASES
============================================================

Handle:

1. Offering has no feasible placement.
Return infeasible diagnostic.

2. Teacher has no availability.
Return diagnostic.

3. Course requires lab but no lab room exists.
Return diagnostic.

4. Room capacity too small.
Return diagnostic.

5. Manual lock impossible.
Return diagnostic.

6. Time slot duration cannot fit at end of day.
Do not create placement.

7. Overlapping availability ranges.
Resolve with precedence:
unavailable > preferred > available > discouraged.
Actually discouraged should be allowed, unavailable forbidden. If both unavailable and preferred overlap, unavailable wins.

8. Missing teacher profile limits.
Use safe defaults but warn in diagnostics.

9. Previous term missing.
Do not penalize diversity.

10. candidate_count too high.
Limit to reasonable max, for example 10.
